# expai 0.0.1.15

The help links of the extension open the help center directly instead of going through the redirect `expai/help`.
Works with Exponential 6.0.14 and later; on 6.0.14, which has no help center, the links still lead to `expai/help`,
which opens the same page on GitHub (`https://github.com/se7enxweb/expai/blob/v0.0.1.15/doc/<page>.md`).

## Added

- Added: `expAiHelpLinks::link()` and the template operator `expai_help_url` (`{expai_help_url( 'vector' )|ezurl}`):
  the address of a help page, in the help center (`exphelp/viewer/ext/expai/<page>.md`, the index
  `exphelp/extensions/expai` for no page) where the kernel has one and the user holds `exphelp/read`, otherwise
  `expai/help/(page)/<page>`. Templates name only the page; the page names are mapped in `expAiHelpLinks`.
- Added: `expAiHelpLinks::menuFallback()`, a listener of the kernel's event `request/input`
  (settings/site.ini.append.php): on a kernel without the help center (Exponential 6.0.14, or exphelp.ini
  `[IndexSettings] ActiveExtensionDocs=disabled`) it points the menu entry EI: Help at `expai/help` and drops its
  `exphelp/read` policy, for the request only; with the help center it changes nothing.

## Updated

- Updated: Dashboard > EI: Help links to `exphelp/extensions/expai` and is shown to users who may read the help center
  (`PolicyList_expai_help[]=exphelp/read`), whatever expai policy they hold: a user with only `expai/summary` who may
  read the help still sees it.
- Updated: The dashboard's Help link and every "?" link (the dashboard, the Intelligence tab, Vector, chains, the
  missing alt text report) link to their page in the help center directly.
- Updated: `expai/help` and `expai/help/(page)/<name>` keep redirecting, for old bookmarks and for kernels and users
  without the help center.
- Updated: Tests (`expAiHelpLinksTest`, `expAiMenuPolicyTest`) and the documentation (index.md, dashboard.md,
  permissions.md, architecture.md, troubleshooting.md).
