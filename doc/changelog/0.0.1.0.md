# expai 0.0.1.0

The first release of Exponential Intelligence (Powered by Claude from Anthropic): a writing assistant for the
Exponential 6 administration interface that writes drafts as the logged-in editor, with the editor's permissions,
and never publishes on its own. Every item below is new in this release; the Updated, Removed and Renamed entries
describe how parts changed while 0.0.1.0 was being built, for readers of the development history.

## Added

### Writing with the assistant

- Added: The Intelligence tab on the content full view (content and media sections): a conversation per user and
  node, with lookups and draft writing through tools, run as the logged-in editor.
- Added: The conversation history: one collapsible row per exchange (only the latest open), Expand all, Collapse
  all, Show older, kept on the server per user and node.
- Added: A bounded context window: older exchanges become a short summary, the last ones are sent word for word
  (`[AssistantSettings] ContextWindowTurns`).
- Added: The content tools `get_node`, `list_children`, `get_tree_context`, `list_creatable_classes`,
  `get_class_definition`, `create_draft` and `update_draft`, registered in expai.ini.
- Added: "Save as drafts" and "Send for approval" (the regular publish operation as the editor), with a hint per
  draft whether an approval workflow applies; Discard.
- Added: The edit form integration through content.ini `AdditionalTemplates[]`: "Fill the fields" from a brief and
  the field actions Write, Rewrite, Shorten, Translate and Suggest, filling Tiptap, the Online Editor or plain fields
  for review.
- Added: Editor presets per class (Suggest title, Write summary, Meta description, Keywords, including xrowmetadata
  parts), an Improve menu on every text field and a "Defaults in use" line with the model, region, lane and cost of
  one click; the presets in the command palette.
- Added: Alt text for images: a vision model suggests the alt text of an image field in the edit form within the
  data policy ("Write alt text", "Decorative (empty alt text)"), and the "Missing alt text" report queues
  suggestions for a subtree as drafts within the budgets.
- Added: The "Exponential Intelligence" label on versions written by expai: in My drafts, the drafts page, version
  views, edit forms and approval items.

### Vector and threads

- Added: Threads: every conversation of the Intelligence tab and every Vector run is a thread with a scope, a mode,
  a model, a state and its cost; private to its owner, readable by the approvers of its versions; retention of
  events, proposals and checkpoints.
- Added: Vector (`expai/vector`), the workspace of threads, with scope, plan and write modes, model and lane,
  run, stop and queue, the command palette (Ctrl/Cmd+K) and keyboard shortcuts of one's own.
- Added: Background runs of threads: turns of slow models run in the job queue and are followed live in Vector and
  the Intelligence tab.
- Added: Staged review in Vector: write tools propose changes that the editor accepts, rejects or edits per field
  and part before anything is written, with conflict detection and rebase.
- Added: "What changed" for drafts written directly (the Intelligence tab, Vector threads with Review: Direct): the
  diff against the version the draft was based on, per field and part, and Revert for a part or a whole field into
  the same draft, with conflict detection; owner only, edit permission checked at revert time, never published.
- Added: Plan mode in Vector: bulk work starts with a plan and a cost estimate, calibrated from finished plans, that
  the editor approves before anything is staged; the expected cost is reserved.

### Providers, models and the data policy

- Added: A provider registry (`[ProviderSettings]`, `[Provider_<id>]`, `[Model_<alias>]`) with the adapters
  `anthropic` and `openai_chat` (OpenAI Chat Completions and every compatible service: the Hugging Face router,
  OpenRouter, Mistral, Ollama, vLLM ...) and custom provider classes; native and prompted tool calling.
- Added: The model picker with region, relative cost, tool mode and state; the policy `expai/model_use`
  (limitation Provider).
- Added: The fallback to the default model when the chosen model is stopped, unreachable, timed out, no longer
  allowed, removed or kept away by the data policy; stopped local models marked in the pickers.
- Added: A data policy: region and retention per provider, rules per section and class, enforced in the panel,
  every tool, the edit form, alt text, MCP and the web search, and recorded per request.
- Added: The tool-calling probe (`bin/php/expaiprobe.php`, 15 tasks) and the write gate: only trusted models or
  models with a passed live probe write drafts.
- Added: Local open-weight models: a pinned Ollama on the loopback address with a capped systemd unit, a root-owned
  spool helper with an allowlist, an idle timer, and `expai/models` to start, stop, pull, remove and test them.
- Added: "Load model" on `expai/models` for models of a local server: loads the model into memory as a job
  (`[ModelTest] LoadKeepAlive`) and shows until when it stays loaded.
- Added: The web budget (`[WebBudget]`): the field actions, presets and the fill of the edit form refuse a slow or
  local model with a clear message instead of running into the web server's timeout.
- Added: The provider proof report (doc/provider-support.md): what is proven live, against docs-derived mocks, or
  not yet, with mock servers of Hugging Face, OpenRouter, the batch APIs and MCP.
- Added: Melious (EU inference of open-weight models) as a shipped, inactive provider (`[Provider_melious]`,
  `Flavor=melious`, `Region=eu`, `Retention=zdr`) with the models GLM 5.3 Flash, GLM 5.3, DeepSeek V4 Flash 0731 and
  DeepSeek V4.1 Flash; the cost Melious reports with every answer (`billing_cost.credits`) is stored as the reported
  cost; a unit test against recorded answers (`tests/expaimelious_test.php`) and a demo script (doc/demo-melious.md).
- Added: Prices in another currency: `[Provider_<id>]` / `[Model_<alias>]` `PriceCurrency` and `[Pricing]
  ExchangeRates[]` convert a provider's prices and reported costs into the site's currency (unknown without a rate).
- Added: `[Model_<alias>] ContextTokens`, the context window of a model, shown on expai/models.
- Added: The reference rates of the European Central Bank for prices in another currency (`[Pricing]
  ExchangeRateSource=ecb`): fetched once a day by the job `expai.exchange.rates`, the cronjob part
  `expai_exchange_rates.php` or `./console ext:expai:exchange-rates`, kept with their date, shown on expai/models;
  `ExchangeRates[]` is the fallback or, with `ExchangeRateSource=settings`, the override.
- Added: The test prompt of expai/models measures the time to the first token on a provider that streams
  (`[Provider_<id>] Streaming=enabled`, Melious).

### Tools beyond the content tree

- Added: MCP tools in the panel: the in-process bridge to expmcp (its bridge-safe read tools, as the current user,
  with the data policy) and a streamable-HTTP client for external MCP servers with an allowlist, an SSRF guard, a
  region and retention check and no writes after an external result; the policy `expai/mcp`.
- Added: The web and history tools `web_fetch` (allowlisted domains, robots.txt, pinned addresses), `web_search`
  (Brave Search, under the data policy) and `project_history` (the team's git repositories); the policy `expai/web`.
- Added: Service tools: the read services of expservices that opt in are tools of the assistant, named as expmcp
  names them, run as the editor with the service's own access checks; the policy `expai/services`.

### Safety switches

- Added: The master switch (`[AISettings] Enabled`, `DisabledSiteAccesses[]`) at every entry point, and the veto
  hook (`[RequestVeto]` rules and the ezpEvent filter `expai/request/veto`) that can refuse any request to a provider
  with a reason; queued requests are held while expai is off.

### Usage, cost and limits

- Added: Usage tracking in `expai_usage_log` (one row per request: tokens, latency, tools, errors, rate limit
  headers, provider, region, retention; user ids only), a retention cron part, and an estimated cost from a price
  table, model aliases or the cost a provider reports.
- Added: Limits per conversation, session, user and day or month, site month and provider.
- Added: The dashboard page `expai/dashboard` (period and Mine / Site, status, cost, tokens, requests and drafts
  with trends, a chart per day, limits and rate limits, top users, Start writing, recent drafts, versions waiting for
  approval), the dashboard block and the log page `expai/log` (turns, filters, totals, CSV).
- Added: The "Models" card of the dashboard: per model the requests, success rate, errors by kind, how often the
  fallback replaced it, median and 95th percentile latency, tokens per second, time per turn, cost, latency per day,
  the newest test prompt and probe, slow models flagged; each model links to its requests and errors in the log.
- Added: Links from prompts started outside Vector to their live record: "Watch this run" after Start writing (the
  thread, its requests, its job), the test prompt to its request and job, several chain runs started at once to each
  run and job group, queued alt text suggestions to their job group; the log filters `(request)` and `(thread)`.
- Added: "View record" after a field action, a preset or an Improve entry in the edit form (next to the note and Undo,
  also after a failure): the request's row in the usage log, and its job when it ran as one, in a new tab.
- Added: The printable "EI: Summary" page (`expai/summary`, Setup > EI: Summary) for a data protection officer: providers,
  regions, retention, key sources (never a key), roles, lanes, data policy, limits and the tools that reach outside
  the site; the policy `expai/summary`.
- Added: The audit trail of Exponential Intelligence: model requests (failed and refused ones too), drafts written
  and their states (kept, sent for approval, published, discarded, back in progress), chain actions, model actions,
  budget holds and resumes, calls of external MCP tools and policy migrations are recorded by the kernel's audit
  writer into the channel `ai`, with who, when, which node, model, provider, region and the estimated cost, never a
  prompt, an answer or a key (`settings/audit.ini.append.php`, `classes/audit/`, doc/audit-trail.md).
- Added: Exponential Intelligence in the audit console: a dashboard panel (requests, failures, refusals, drafts
  written and published, budget holds, estimated cost, top users and models), the sidebar entries "AI events" and
  "EI: Log", links from the console, recent events, charts, alerts and export into the channel and into `expai/log`
  with view parameters, the fields and links of an event, a chart per day, the alert rule `expai_request_failures`,
  and the channel "Exponential Intelligence" in the Channel limitation of `audit/read`.
- Added: The CSV export of the channel `ai` (audit/export/(channel)/ai, exp:audit export --channel=ai --format=csv)
  has the request's provider, model, model alias, region, purpose, lane, tokens in and out, latency, HTTP status,
  draft status, fallback (model and reason), estimated cost and currency after the generic columns
  (`expAiAuditSource::exportColumns()`); never a prompt, an answer or a key. The sidebar entry "AI events" is left out
  for a user whose `audit/read` is limited to other channels (the kernel's audit menu does that for every source).

### Queued work

- Added: Lanes of the providers (standard, flex, batch, fast), the lane policy, provider batches of the Anthropic,
  OpenAI, Gemini, Mistral and OpenRouter batch APIs, through the job queue (extension expqueue).
- Added: Budgets for queued requests: a monthly site budget and job group budgets with reservations, holds and
  resume; `expai/budgets`.
- Added: AI chains: multi-step writing through the job queue (write, review and revise until it passes, SEO and
  links, a human checkpoint, translate), defined in expai.ini, with run budgets; `expai/chain` and the policy
  `expai/chain`.
- Added: A diff engine of content versions and languages, with segmenters per datatype, stable hunk ids, metrics,
  compare and apply.
- Added: Translation sync: after the source language changed, each translation is classified as no change, patch or
  full retranslation, cheap patches are queued and the others wait for an editor; a workflow event and the
  Translations section of the Intelligence tab; the policy `expai/translation_sync`.
- Added: Content packages on the kernel's packages (classic or JSON format): AI provenance as package metadata,
  import as drafts only, the draft log, queued imports of large packages, `expai/packages` and
  `./console ext:expai:package`; the policies `expai/package_import` and `expai/package_export`.

### Administration and documentation

- Added: The policies `expai/write`, `expai/log` and `expai/settings`, and the ezjscore functions of `expai::`,
  `expaivector::`, `expaitranslation::`, `expaipreset::` and `expaialttext::`.
- Added: The 15 tables for MySQL, PostgreSQL, SQLite, Oracle and MongoDB, and `bin/php/expaischema.php` to install
  and upgrade them on every engine.
- Added: Extension points for tools, field actions, panel and edit form sections, providers and JavaScript hooks,
  with the example extension `doc/examples/expaiexample`.
- Added: Help pages in the administration interface: `expai/help` renders the extension's documentation (a
  Markdown subset, every character escaped), with a "?" link on the dashboard, the Intelligence tab, Vector, EI:
  Summary, the "Missing alt text" report, chains and content packages.
- Added: Menu entries EI: Vector, EI: Chains, EI: Log and EI: Help (Dashboard), Missing alt text (Design) and EI:
  Summary, EI: Models, EI: Budgets and Content packages (Setup), with expqueue's Job queue right after EI: Budgets.
- Added: Translations eng-US and ger-DE, and the untranslated template.
- Added: Documentation of every part (doc/index.md), the install and upgrade checklist (INSTALL.md) and the provider
  proof report.
- Added: The compact prompt for local models (`PromptProfile=compact`): a short system prompt, only the tools the
  editor's message needs and a short snapshot of the open page, so a plain question reads 268 tokens instead of 6,543
  ([../local-models.md](../local-models.md), "Making a local model usable"); Qwen3.5 2B as a faster local option.
- Added: A PHPUnit suite (`phpunit.xml.dist`, run with the installation's PHPUnit): unit tests of the classes, and
  every script test of `tests/` run through a wrapper that also checks that no check is lost; mock end-to-end runs
  in the group `e2e`, the run against a real model in the group `provider` (excluded by default); coverage measured
  with Xdebug, including the script tests ([../testing.md](../testing.md)).
- Added: The registries of expai in the extension point survey (`settings/rad.ini.append.php`): providers and their
  types, models, batch APIs, lanes, tools, web search providers, MCP servers and bridge tools, service tools, chains
  and their steps, field actions, presets, request appliers, diff segmenters, panel sections and panes, history
  repositories, data policy and request veto rules, each entry counted and checked on Setup > RAD tools
  ([../extending.md](../extending.md), "7. Registries in the extension point survey").

## Updated

- Updated: A summed cost (the log's totals, per day, per user and per provider, the dashboard's Estimated cost and
  limits, the monthly budget, EI: Summary) is the sum of the priced requests with "15 requests without a price" beside
  it, instead of "not configured" as soon as one request had no price; the note links to those requests
  (`expai/log/(unpriced)/1`).
- Updated: After "Send for approval" or "Save as drafts" the Intelligence panel's thread no longer says "To review"
  once none of its drafts waits for a decision, the exchange shows "Published as version N" (or "Sent for approval
  as version N") below the answer, which stays as the model wrote it, and the page header shows the new version.
- Updated: The address of a Vector thread that was deleted (or that the user may not open) answers 404 with "This
  thread no longer exists" and a link back to Vector, instead of the workspace with an error.
- Updated: The drafts of a package written with Exponential Intelligence (package metadata `expai.ai-generated`)
  are recorded in the draft log from the kernel's event `package/install/drafts`, whichever way the package is
  installed as drafts (Setup > Packages, `ezpm install --as-drafts`, a background install).
- Updated: The in-process bridge to expmcp runs through expmcp's own bridge seam (`expMcpBridge`, expmcp 0.3.1 or
  later), with only the tools expmcp declares bridge-safe.
- Updated: The local model helper creates the tuned model through Ollama's API instead of running a command, and
  names its request handler apart from the file handle it shadowed.
- Updated: A slow local model says how long a step takes; the probe takes a timeout.
- Updated: Content packages are the kernel's packages in the classic or the JSON format (validation, the report by
  remote id and the install as drafts are the kernel's); expai keeps the provenance metadata and the label.
- Updated: The OpenAI-compatible adapter sends image blocks as `image_url` parts, the Anthropic models of the site
  settings can look at images, and logged requests never keep the pixels of an image.
- Updated: Vector's event stream reaches the browser as it happens on PHP-FPM and on Velocity (every output buffer
  removed; a followed background turn keeps its own event cursor).
- Updated: The documentation uses American spelling throughout, and the dashboard's note on the organization's
  spend limit with it.
- Updated: "Test prompt" on `expai/models` runs as a job of the job queue (`expai.model.test`) instead of in the page
  request, which ended in a 504 while a local model loaded; the page follows the job and shows the time to the first
  token, tokens per second in and out, the total time, the cost and the answer.
- Updated: Background runs of a local model have their own time limit (`TimeoutBackground=900`) and keep the editor's
  model after a timeout; Ollama keeps the model and its cached prompt loaded (`KeepAlive`); the local Modelfiles run 2
  threads (twice as fast as 4 on a busy host); the Models card shows the median prompt and the share from the cache.
- Updated: An assistant message sent back to an `openai_chat` provider leaves out the null fields and the
  `provider_specific_fields` a proxy adds to its answers.
- Updated: A chain run whose insert failed (SQLite: the database was locked by another writer) is no longer stored
  as the row 0 with a job group that does not exist: the start says "The chain could not be started. Please try
  again.", and a run without an id is neither stored nor read.
- Updated: The probe follows a lookup before the write (`follow_ok` on create_draft and update_draft): the lookup is
  answered with a scripted result, at most `[ProbeSettings] FollowRounds` times, and the next call is graded; the
  result records how often.
- Updated: The hint of the chain form names the budget of the chosen chain and the item count follows its MaxItems,
  also when the chain is changed.

## Removed

- Removed: The page Setup > Content packages (`expai/packages`), the command `./console ext:expai:package`, the
  policies `expai/package_import` and `expai/package_export`, the job type `expai.package.import`, the classes
  `expAiPackageService`, `expAiPackageRecord` and `expAiPackageImportHandler`, and the table `expai_package`
  (`bin/php/expaischema.php --install` drops it): Setup > Packages and `ezpm` of the kernel do all of it (upload
  with validation, the report of what an install meets, install as drafts, in the background for a large package,
  the package's files, a package from a subtree in either format).
- Removed: The Exponential Intelligence badge next to links to versions it wrote; only the page of the version
  itself shows the banner.
- Removed: The package format of expai's own (exporter, importer, validator, diff and schema, written during the
  development of 0.0.1.0): content packages are the kernel's packages.

## Renamed

- Renamed: The menu entries carry the prefix "EI:", and Missing alt text moved from the Dashboard menu to the Design menu.

## Known limits of this release

- Hugging Face and OpenRouter are proven against documentation-derived mocks and with a live keyless request only;
  OpenAI, Gemini and Mistral against mocks only ([../provider-support.md](../provider-support.md)).
- A local model on a shared CPU host takes about a minute for a plain question and two to four for a page or a change;
  use dedicated cores or a hosted open-model provider for many editors.
- Service tools are read-only; writes are planned as staged proposals.
- expmcp's HTTP transport has no authentication of its own: run it read-only behind an authenticating proxy.
- Text and images only: no image generation, speech or embeddings.
