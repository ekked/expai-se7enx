# expai 0.0.1.3

## Updated

- Updated: Draft log entries whose content object was removed since (or purged from the trash) no longer write an
  "Object not found" error to the debug output. The dashboard block, the Exponential Intelligence dashboard and
  expai/log looked up each entry's object with `eZContentObject::fetch()`, which logs an error for every id it does
  not find, twice per row. They now check a whole page of entries in one query (`expAiObjects::existing()`,
  `expAiDraftLog::markObjectsThatExist()`) and list such an entry as "(removed)" with the state "deleted" and no
  link. The Intelligence panel and Vector leave them out, as before.
- Updated: The cronjob `expai_prune` marks the draft log rows of removed objects `deleted`; the rows are kept.
- Updated: Every other lookup of a stored object id (staged changes, checkpoints, plans, chain runs, queued jobs,
  alt text reports, the publisher) goes through `expAiObjects::fetch()`, which returns null without a debug error.
- A new test, `tests/phpunit/unit/core/expAiDeletedObjectsTest.php`, checks that a logged id without an object
  gives no debug error and no link.
